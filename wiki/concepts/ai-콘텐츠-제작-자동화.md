# AI 콘텐츠 제작·게시 자동화

AI 에이전트(예: Codex)를 **창작자가 아니라 변환기·실행기**로 활용해, 원본 기록을 콘텐츠로 변환하고 게시·측정·개선까지 반복 운영하는 방식. 김솔의 인스타툰 333만 조회 사례에서 정리.

## 핵심 명제

> 병목은 "이미지 한 장을 잘 만드는 것"이 아니라 **기록 → 제작 → 게시 → 데이터 분석 → 다음 소재 선정**의 전체 운영 루프다.

이미지 생성 품질보다 **목표 설정 → 데이터 수집 → 다음 콘텐츠 반영**의 순서가 성과를 좌우한다.

## 운영 루프

1. **기록(사람)** — 원본 소재 축적 (AI는 빈 곳에서 만들지 못함)
2. **변환(AI)** — 컷 분할, 장면·대사·반전 배치
3. **생성(AI)** — 이미지 컷 생성, 사람이 흐름·말투·기억 일치 확인 후 승인
4. **게시(AI)** — 브라우저 직접 조작 → Buffer → Threads 예약 발행
5. **측정** — 지표별 분리 분석
6. **개선** — 반응 데이터로 소재 우선순위·구성·프로필 재설계

## 지표 해석 프레임

| 지표 | 의미 |
|------|------|
| 조회수 | 확산 정도 (알고리즘 영향 큼) |
| 좋아요 | 가벼운 공감 |
| 댓글 | 경험 환기 (→ 공감형 소재) |
| **공유** | 추천 의향 (→ 상황형 소재, 한 장면으로 이해되는 콘텐츠) |
| **저장** | 재방문 의향 (오래 남을 소재) |
| 팔로워 증가 | 연재 기대 |

- **공유·저장 중시**: 독자가 한 번 더 행동해야 생기는 신호라 알고리즘 의존이 적음
- 목적별 분류: 조회수 高 = "확산력", 공유·저장 高 = "오래 남을 소재"

## 사람 vs AI 역할 분담

- **사람**: 기록, 목표 설정, 최종 승인, 데이터 해석
- **AI**: 변환, 생성, 게시 실행 (반복 작업)
