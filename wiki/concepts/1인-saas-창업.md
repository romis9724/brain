# AI 시대 1인 SaaS 창업

Claude Code, Cursor 등 AI 코딩 도구로 혼자 SaaS를 만들어 수익화하는 창업 패턴. 기술보다 고객 문제 해결과 PMF 검증이 핵심.

## PMF(Product-Market Fit) 검증 원칙

**PMF 판별법**: "런칭하자마자 결제가 들어오면 PMF다"
- 유료 전환 지표를 꾸준히 모니터링
- 무료 체험 후 유료 전환율이 지속 상승 = PMF 신호
- B2C처럼 보여도 사용 패턴이 B2B2C로 진화할 수 있음 (학교→교육청)

## 오버 엔지니어링 함정

1인 창업 초기에 가장 흔한 실패 패턴:
- **얼리어답터 요구사항 ≠ 대중 요구사항**: 첫 번째 고객은 상위 1% 파워유저일 가능성
- **기술 과잉**: 멋진 기능보다 고객이 실제로 원하는 것 (보안, 단순성)
- **불필요한 복잡성**: 팀 작업 도구(PR, 브랜치, 스펙 관리)를 1인 초기 제품에 도입

> "내가 화려한 기술을 쓴다는 것이 중요한 게 아니다. 기술이 고객의 일을 대체할 때 의미가 있다."

## 기술 매몰 경계

AI 시대의 역설: 기술이 좋을수록 기술에 빠지기 쉬움
- 제품명에 'AI' 붙이는 것이 오히려 특정 도메인(심리상담 등)에서 역효과
- 엑셀 템플릿, 로컬 앱 등 기술적으로 단순한 해법이 더 강한 PMF를 만들 수 있음
- **"엑셀로 뭔가 하고 있으면 거기 기회가 있다"** — 기술 과잉이 아닌 문제 과잉 탐색

## 해자(Moat) 구축 전략

기능은 복제 가능 (CRUD 서비스 = 한 달이면 복제)

진짜 해자 옵션:
1. **커뮤니티 & 네트워크**: 사용자들의 상호 연결, 멘토-멘티 생태계
2. **도메인 특화 콘텐츠**: 역량 강화 강의, 자료, 노하우
3. **데이터 록인**: 누적된 고객 데이터가 타 서비스로 이전 어려움
4. **B2G 인증**: 공공기관 인증·등록으로 도입 허들 제거

## Claude Code 1인 개발 루틴

위노트 사례 기준:
- **도구**: Claude Code (터미널 기반, IDE 불필요)
- **프로세스**: 프롬프트 중심 개발 → 손 QA → 8시 전 배포
- **생략하는 것**: 브랜치, 테스트코드, PR, 스펙 문서
- **유지하는 것**: Claude CLAUDE.md/Skills로 컨텍스트 최소 관리

초기 단계에서 팀 협업 도구(Conductor, OpenSpec 등)는 오버 엔지니어링. 규모 커질 때 도입.

## 고객을 팬으로 만드는 CS 전략

- **24시간 직접 응대**: 개발자가 직접 버그 수정·피드백 → 고객이 서비스 공동창조자로 인식
- **빠른 버그 수정**: AI로 30분~1시간 내 수정 → 즉시 공유 → 신뢰 형성
- **팬 효과**: 버그 환불 요청 0건, "쉬엄쉬엄 하세요" 역걱정하는 고객 등장

## 니치 마켓 선택 원칙

좋은 니치의 조건 (위노트 사례):
- 현재 엑셀/수동 작업으로 처리 중인 반복 업무
- 도메인 특수성으로 일반 SaaS가 진입 어려운 시장 (데이터 보안, 규정 등)
- 적은 수의 사용자지만 절실히 필요 (상담교사 2~3시간 행정 → 10분)
- 입소문 기반 바이럴 가능 구조 (학교 내 → 학교 간 → 교육청)
