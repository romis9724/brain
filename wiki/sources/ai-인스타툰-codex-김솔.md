# AI로 인스타툰 만들기 — 6주 만에 333만 조회

[[wiki/entities/people/김솔|김솔]]이 자신의 육아기록을 Codex로 인스타툰(만화)으로 변환·게시하고 데이터로 개선해, 2026-05-07~06-17 **6주간 79개 인스타툰, 누적 333만 회 조회**를 달성한 과정 기록. (Threads `@home_dad_sol`)

## 요약

같은 육아기록이라도 **글 → 만화**로 형식을 바꾸자 반응이 크게 달라졌다(조회·댓글·공유 증가). 저자는 Codex를 "창작자가 아니라 변환기"로 사용해 컷 분할·이미지 생성·브라우저 조작 게시(Buffer→Threads 예약 발행)까지 자동화했다. 핵심 교훈은 **이미지 한 장의 품질이 아니라 기록→제작→게시→데이터 분석→다음 소재 선정의 전체 운영 루프**가 병목이자 자산이라는 점.

## 핵심 포인트

### 형식 전환 — 기록은 그대로, 형식만 바꿈
- 글은 독자가 상황을 머릿속으로 재구성해야 함 → 만화는 표정·반응을 먼저 보여줌
- 처음 보는 사람도 맥락을 덜 놓치고 웃음 포인트가 빠르게 전달
- Codex의 역할 = **변환기**, 시작점은 여전히 사람의 육아기록

### 목표 설정 — 조회수가 아니라 출판 가능성 검증
- 진짜 목표: "이 육아기록이 책으로 묶일 수 있을까?"
- 과거 Pieceful(육아기록 앱) → 출판 계약 경험에서 출발
- 목표가 정해지자 데이터가 단순 성과가 아니라 **독자 행동을 읽는 기준**이 됨

### Codex가 맡은 일 (사람은 기록·승인에 집중)
1. 육아기록을 여러 만화 컷으로 분할 (장면·대사·반전/웃음 포인트 배치)
2. 컷별 이미지 생성 (캐릭터 스타일·말풍선·한글 대사 확인·수정)
3. 게시용 파일 정리 → **브라우저를 직접 조작**해 Buffer 접속 → Threads 게시물 생성·예약 발행
- 사람은 흐름·말투·기억 일치 여부 확인 후 최종 컷 승인만 담당

### 데이터 — 조회수보다 먼저 보는 지표
- 조회수(확산) / 좋아요(가벼운 공감) / 댓글(경험 환기) / 공유(추천 의향) / 저장(재방문 의향) / 팔로워 증가(연재 기대)
- **공유·저장 중시** — 알고리즘 영향이 큰 조회수와 달리, 독자가 한 번 더 행동해야 생기는 신호
- 판단 기준 분리: 조회수 高 = "확산력 있는 소재", 공유·저장 高 = "책으로 묶었을 때 오래 남을 소재"

### 데이터 기반 개선
- 여러 컷으로 넘겨 읽는 구성 채택 (맥락·반전이 중요한 콘텐츠 특성)
- 프로필을 "다음 콘텐츠를 볼지 판단하는 첫 화면"으로 재설계
- 소재 선정 기준 변경: 내가 재밌던 것 → 독자가 반응한 지점 우선
- 댓글 긴 소재 = 공감형, 공유 많은 소재 = 상황형으로 분류해 우선순위 결정

### 상위 콘텐츠
- 「방음이 좋은 줄 알았습니다」 430,606회 / 「피자에 까다로운 그녀」 352,459회 / 「창문 속 윤슬」 307,569회

## 인사이트

- "AI로 무엇을 만들 수 있나"보다 **목표 설정 → 데이터 수집 → 다음 콘텐츠 반영**의 순서가 더 중요
- Codex의 브라우저 컨트롤을 통한 게시 자동화는 [[wiki/concepts/루프-엔지니어링|루프 엔지니어링]]의 생활 적용 사례 — 기록→제작→게시→피드백이 하나의 반복 시스템
- AI는 빈 곳에서 이야기를 만드는 도구가 아니라, **이미 쌓아둔 기록을 더 많은 사람이 읽을 형식으로 바꾸는 도구** — [[wiki/concepts/pkm|PKM]]의 "기록이 자산" 명제와 통함
